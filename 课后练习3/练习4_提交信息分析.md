# 练习4：开源项目提交历史分析

## 项目：Git (https://github.com/git/git)

## 好的提交信息示例

**提交标题：** merge: load default config variables via config API

**正文：**
The default config variables are currently read via environment variables.
However, this does not work well with the config API which is used by other
parts of Git. This patch changes the default config to be loaded via the
config API, making it consistent with other config loading mechanisms.

**为什么好？** 标题清楚说明了改了什么，正文解释了"当前做法有什么问题"、"新做法是什么"、"为什么这样做"，背景完整。

---

## 差的提交信息示例

**提交标题：** fix bug

**为什么差？** 完全没有说明是什么bug、在什么情况下发生、怎么修复的。维护者需要读整个diff才能知道发生了什么，浪费大量时间。

---

## 重写差的提交信息

**原标题：** fix bug

**重写后的标题：** fix: 修复 --stat 与 --rename-empty 同时使用时导致的空指针崩溃

**重写后的正文：**
当用户同时使用 --stat 和 --rename-empty 两个选项时，fill_print_name() 函数中会对一个未初始化的指针进行解引用，导致段错误。

根本原因是 --rename-empty 逻辑在计算重命名信息时，没有为 stat 输出准备有效的数据结构。

修复方法：在 diff 统计逻辑中增加空值检查，确保在调用 fill_print_name() 之前指针已经正确初始化。

影响范围：仅影响同时使用这两个选项的场景，不影响其他 diff 输出。
